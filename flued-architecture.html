Architecture and Training Trace

FLUED v0.4 -> v3.4

每次改架构，都绑定一个被观察到的问题

这里不把版本变化写成“功能列表”。每个节点都说明：上一版什么地方失效，训练或评估怎样被修正，当前证据实际支持到哪里。v3.4 是可运行、可归因的研究系统，不是已经冻结的最终 tokenizer。

Research Lineage

独立迭代，公开吸收，同构后做可证伪的分歧设计

FLUED 不把相关工作包装成“从未存在”。这条路线先由连续语言空间的接口问题启动，随后分别吸收字节级分层、编码率分段和并行块级细化的可检验思想。H-Net 的出现确认了高层分层结构的合理性，也迫使我们把差异写成可做消融的模块，而不是口头创新。

起点

ELF

连续嵌入空间应尽量持续到离散输出前的思想，触发了“byte 不是终点，潜表示才是主干接口”的最初问题。FLUED 仍保留独立可逆 decoder，而非把自身做成生成扩散语言模型。

v3.1

BLT + ByteFlow

BLT 提供 byte 端局部处理、压缩后主干、回译的职责拆分；ByteFlow 将分段与真实计算账本、编码率选择联系起来。FLUED 继承问题框架，不直接复刻它们的主干或 Top-K 路径。

v3.3

DiffusionGemma

块级双向并行细化与自我修正说明语言处理不必逐 token 串行。v3.4 因而使用一次 DiT-style 条件细化，但不宣称已复现其多轮生成或吞吐结论。

v3.3 -> v3.4

H-Net

高层“局部编码 -> 动态分块 -> 压缩主干 -> 回译”与 FLUED 形成结构同构。发现重叠后，路线转为显式比较：边界代理、memory 职责、可替换主干、严格掩码与 emit 预算是否给出可测增益。

这是一条研究谱系，不是性能归因：外部方法的论文结论不转移给 FLUED。当前只主张 FLUED 已把上述借鉴落为可运行组件，并正在做其改进点的消融归因。

Version Evolution

从可逆重建到可训练语言编码器

版本不是线性“更强”。部分早期结果被后续公平协议或代码纠偏降级为历史证据，仍保留以说明决策为什么发生。

v0.4

最小命题

提出 byte -> latent -> byte 的连续可逆翻译问题，建立实验计划。

状态：设计起点
v1

软边界与 tied inverse

纯重建能稳定成功，但未证明潜表示降低下游学习难度；旧 E3 正向 BPB 不能覆盖后来公平 D1。

纠偏：历史 BPB 不作主 claim
v2

去噪、类型先验与扫描

三种子证实稳定重建；去噪比例和压缩权重扫描暴露出多目标竞争与可塑性问题。

纠偏：稳定不等于压缩可控
v3.1

语言编码器分责

拆出 segment、readout、memory；ROI 显示边界仍受符号和容量影响。

转向：重建不再是唯一目标
v3.2.1

strict masked-source

先在 byte 输入侧 mask，再编码。latent no-memory 将小主干补全从 0.1440 提升到 0.1898。

主证据：阻断 clean readout 泄漏
v3.3

职责边界与公开接口

规定 segmentor 不读 memory、memory 只服务 interpreter、decoder 不读 memory。

状态：架构端点，不是性能终点
v3.4

并行 one-shot 与可归因组件

并行 memory、emit、位置编码、小 AR、近似逆 decoder 进入同一套严格补全训练。

状态：动态边界与梯度课程仍待闭环

Current Forward Path

v3.4：一次并行细化，不是多步采样

当前称为 one-shot diffusion-style refinement：训练态向 byte payload 注入一次噪声，DiT-style block 在一次前向中细化连续表示。它采用扩散式条件化和并行计算，不宣称已经验证多步扩散采样。

H-Net 的单阶段层级结构把局部高分辨率处理、动态下采样、压缩主干和原分辨率 decoder 统一在端到端语言模型中。

FLUED v3.4: codec-oriented variant

masked bytesDiT segmentorhard chunk + soft bridgeinterpreter / emit readoutreplaceable backboneshared inverse bytes

结构同构在“局部编码 -> 动态压缩 -> 主干 -> 回译”。分歧是 FLUED 将 backbone 视为可替换的训练/部署接口，memory 不向 backbone 开放，且单独审计硬执行与软反传。

同构不等于等价

两者都解决可学习层级压缩；FLUED 还没有复现 H-Net 的同预算规模结论，不能把 H-Net 的性能外推为自身性能。

撞车后的改进假设

FLUED 将边界、readout 发声、codec memory 和外部主干拆开，目标是让真实计算成本、严格补全和梯度路由分别可干预。

当前阶段

验证改进点，而不是宣告超越：对照 H-Net 的 router/smoothing 视角，审计动态边界课程、emit 容量和共享逆 decoder 的耦合。

切分器不读 memory

边界先由当前 byte/context 决定；memory 不得作为跨 chunk 边界作弊通道。

memory 并行生成

每个 chunk 的摘要只来自自身 span；interpreter 读取 other-memory，当前 chunk memory 被屏蔽。

decoder 不读 memory

只将完成后的 readout 近似反向翻译为 byte，保留 codec 职责边界。

Gradient Ledger

离散执行不等于不可训练，但需要明确代理路径

hard cut 和 hard emit 决定实际 chunk 与实际 backbone token；反向传播借用连续分数的直通代理。每个损失更新的组件不同，不能用一个总 loss 名称掩盖梯度路由。

前向：真实计算账本

  • 阈值或 rate 选择产生 hard chunk IDs、offsets 与长度。
  • fallback readout 永开；extra readout 的 hard emit 决定是否进入 backbone。
  • soft gate 只缩放表示，不会自动减少注意力 token。

反向：连续可塑代理

  • SoftBoundaryBridge 使用 soft + (hard-soft).detach()。
  • emit 使用同类 straight-through gate；价值 target 被 detach，避免自移动标签。
  • confidence 先验单独更新 signed confidence 支路。

40K S0/S1 曲线已证伪“只要更久训练或更短过渡即可恢复”。当前下一步是将 codec 对齐、emit 容量、边界前向执行和边界主任务梯度拆成独立课程。

Order Is Not Free

纯 one-shot 并行表示遇到字符顺序反例

全局并行 refinement 有效率优势，但集合式 pooling 不会天然区分相邻字符交换。固定 chunk 内的 reads / raeds / rxyds 探针显示：没有位置和窄因果修正时，readout 对换序接近不敏感。

开开0.41200.11480.6404位置 + 轻量局部修正产生协同

保留并行主体

DiT-style segmentor、parallel memory 和 chunk 间 readout 保持并行，不回退为逐 byte AR。

位置提供坐标

RoPE 是当前顺序能力下限；prompt ALiBi 是相对距离的可选对照，尚未取代 RoPE。

小 AR 只做低幅度局部残差

GRU 仅在 chunk 内有限 span 串行，不能作为第二个主干或替代位置编码。

本表是早期 1K 定位实验，用于解释“为何引入 RoPE + 小 AR”，不是迁移后 v3.4 的最终性能 claim。
